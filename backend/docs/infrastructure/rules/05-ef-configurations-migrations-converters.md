# 05 — EF Configurations, Migrations and Converters

## 1. Entity configuration placement

Each aggregate/entity configuration must live in:

```txt
Data/Configurations/{BoundedContext}/{EntityName}Configuration.cs
```

Examples:

```txt
Data/Configurations/Identity/UserConfiguration.cs
Data/Configurations/WorkManagement/BoardConfiguration.cs
Data/Configurations/Governance/ShareLinkConfiguration.cs
```

Do not configure large entities inline in `ApplicationDbContext.OnModelCreating` unless it is a global convention.

## 2. Schema rule

Use `DbSchemas` constants.

Do not hardcode schema strings across configuration files.

Allowed:

```csharp
builder.ToTable("boards", DbSchemas.WorkManagement);
```

Forbidden:

```csharp
builder.ToTable("boards", "work");
```

unless `DbSchemas` does not yet have the schema and the PR adds it.

## 3. Table naming

Table names must be snake_case and plural/specific by domain convention.

Example:

```txt
work.boards
identity.users
governance.share_links
ops.outbox_messages
```

## 4. Key rule

Domain `Entity.Id` is generated by domain/factory, not database.

Global convention:

```txt
ValueGeneratedNever()
```

Do not use DB-generated IDs for domain aggregates unless explicitly documented.

## 5. Enum conversion rule

Enums are stored as strings unless there is a documented exception.

Reason:

- easier DB debugging;
- safer across enum reorder;
- stable external reporting.

Max length should be bounded.

## 6. Value object converter rule

Value objects must use value converters.

Existing patterns include:

- `JsonValueConverter`
- `FractionalIndexConverter`
- `SecretRefConverter`
- `JsonDocumentConverter`
- `TokenHashConverter`
- `DocumentSnapshotConverter`
- `UsageMetricKeyConverter`
- `GroupRuleConverter`
- `SyncCursorValueConverter`

When adding a new value object persisted as scalar/json:

1. Add converter in `Data/Converters/`.
2. Add global convention if common.
3. Add unit tests for round-trip.
4. Add migration snapshot validation.

## 7. Owned type rule

Use owned types when value object belongs exclusively to aggregate and has no identity.

Do not create separate table for value object unless:

- it has lifecycle;
- it is queried independently;
- it has permissions/audit;
- it needs indexing at scale.

## 8. Index rule

Every query path must have matching index.

Required for tenant-scoped entities:

```txt
(account_id, workspace_id, id)
(account_id, workspace_id, deleted_at)
```

Feature-specific examples:

```txt
board_id + position
workspace_id + status
provider + provider_id unique
event_id + consumer_name unique
```

## 9. Unique constraints under tenant

Tenant-scoped uniqueness must include tenant dimensions.

Wrong:

```txt
UNIQUE(slug)
```

Right:

```txt
UNIQUE(account_id, workspace_id, slug)
```

Global uniqueness is allowed only for truly global identities, e.g. provider subject or normalized email depending on identity design.

## 10. Migration rule

Migrations live only in Infrastructure.

Do not edit old migrations unless branch is not yet merged and DB is not shared. Otherwise add new migration.

For destructive changes:

- Document why data loss is acceptable or provide migration path.
- Include rollback note if practical.
- Update seed/test fixtures.

## 11. RLS/policy migration rule

If table is tenant-scoped:

- Enable RLS.
- Add policy or explicitly document why RLS disabled.
- Include account/workspace condition.
- Add integration test if high-risk table.

Do not enable RLS without policy in production tables unless intentional deny-all is documented.

## 12. Seed rule

Seed code must be deterministic and idempotent.

Do not seed with random IDs unless test-only.

Seed should:

- use fixed IDs or natural keys;
- upsert safely;
- avoid concurrency conflict;
- not depend on current time unless explicit.

## 13. Configuration checklist

When adding an entity:

- Correct schema/table.
- Primary key configured.
- Tenant dimensions configured if scoped.
- Soft delete column configured if soft-deletable.
- Version concurrency token inherited if aggregate root.
- Required properties max length.
- Enum conversion.
- Value converters.
- Indexes and unique constraints.
- RLS migration/policy.
- Tests.
