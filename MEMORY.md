## 1. Product Identity

Notrelix is an enterprise work-management SaaS platform — a "workspace operating system for teams." It unifies:

- **Notion-like documents** — block-based editor with 16+ block types
- **Monday.com-like boards** — dynamic schema boards with Kanban/Table/Calendar/Timeline/Dashboard views
- **Calendar sync** — two-way sync with Google Calendar

**Core product model:**
```
Workspace
  → Space / Folder
    → Board
      → BoardField (dynamic schema columns)
      → BoardItem (rows/tasks)
      → BoardView (saved view configs — NOT separate data)
```

Kanban, Calendar, Timeline, Table, Dashboard, Form are **views over the same work data**. They are not separate data models.

**Brand personality:** Calm, focused, confident. Low-stimulation app UI; bolder marketing pages.

## 4. Foundation Packages

### `@notrelix/kernel`
Zero internal dependencies. Pure utilities:
- `AppError` / `AppErrorKind` — unified error type (network, auth, forbidden, not_found, conflict, validation, rate_limited, server, aborted, unknown)
- `applyServerValidationErrors` — bridges server validation errors into react-hook-form
- `getFormErrorMessage` — Vietnamese default fallback
- `generateCorrelationId` — UUID v4
- `invariant` / `assertNonNull` — assertion helpers
- `parseEnv` / `env` — Zod-validated environment variables

### `@notrelix/contracts`
API client and endpoint definitions. Framework-neutral (no React):
- `api` singleton — GET/POST/PUT/PATCH/DELETE with auto-retry on 401, CSRF token, correlation ID
- `endpoints` — typed URL constants/factories for: auth, users, workspaces, pages, blocks, boards, lists, cards, checklists, comments, notifications
- `createNotrelixClient(config)` — factory for isolated client instances
- `ApiError`, `ValidationError`, `PaginationParams`, `PaginatedResponse`

### `@notrelix/platform`
Platform abstraction layer. Introduces React:
- **Permissions:** `hasPermission(role, permission, context?)`, `useCan()` hook, `PermissionGuard`, `PermissionProvider`. 22 permissions across 4 roles (owner, admin, member, viewer)
- **Auth:** `PlatformUser`, `PlatformAuthContext`, `useAuthFailureListener`, `emitAuthFailure`
- **Navigation:** Adapter pattern — `NavigationAdapter`, `NavigationProvider`, `useNavigate`, `useSearchParams`, `usePathname`, `useLink`
- **Config:** `createMockModeChecker` — feature flag mock mode (docs, billing, search, governance, automation, integrations, work-management)
- **Routes:** `routes` constant — typed route path helpers

### `@notrelix/query`
TanStack Query v5 configuration:
- `createQueryClient()` — staleTime 30s, gcTime 5min, retry up to 2, no retry on auth/forbidden/not_found/conflict/validation errors
- `queryKeys` — hierarchical key factory for workManagement (boards, cards)

### `@notrelix/realtime`
WebSocket client. Zero deps:
- `RealtimeClient` — connect, subscribe, disconnect, auto-reconnect
- `BoardPatchEvent`, `BoardPresenceEvent`

### `@notrelix/observability`
Telemetry placeholder. `trackEvent(name, properties?)`.

## 15. Key Architectural Patterns

### Factory Pattern (Dominant)
Features export `createXxx` factory functions accepting `{ api, endpoints }`:
```ts
const LoginForm = createLoginForm({ api, endpoints });
const useWorkspaceList = createUseWorkspaceList({ api, endpoints });
const DocPageScreen = createDocPageScreen({ api, endpoints });
```

### Layered Dependency Rules
```
kernel (zero deps)
  → contracts, platform, query (depend on kernel)
    → runtimes (depend on platform)
      → ui-* (depend on ui-tokens only)
        → product/* (depend on foundation + ui)
          → features/* (depend on foundation + ui)
            → apps (depend on everything)
```

### Framework Boundary
- `contracts`, `kernel`, `realtime`, `observability` — **no React, no DOM**
- `platform` — introduces React hooks/contexts
- `query` — wraps TanStack React Query
- `ui-*` — framework-specific (web or mobile)
- `product/*` — core is framework-neutral, web/mobile are framework-specific

### Unified Error Model
`AppError` flows through contracts → query (retry logic) → platform (permission/form handling). The `AppErrorKind` discriminant drives all error routing.

### Guard Pattern
Two-layer security: `AuthGuard` (session) → `WorkspaceGuard` (workspace access).

### Conditional Shell Rendering
Content routes use `WorkspaceTabbedRouteFrame`; other routes use regular topbar.

## 17. Frontend Rules (from RULES.md)

1. **UI Placement:** Business-aware → `features/`, route-specific → `app/**/_components/`, primitive → `components/ui/`
2. **Import Boundaries:** One-way flow: app → features → lib → external; ui → external only
3. **API Files:** Pure HTTP clients only — no React, no hooks, no side effects
4. **State Separation:** Server state → TanStack Query; Local UI → useState; Shareable UI → URL params; Global UI → Zustand (never backend data)
5. **Query Keys:** Must use centralized `queryKeys` factory
6. **Forms:** React Hook Form + Zod. Schemas in `features/<feature>/schemas/`
7. **Permissions:** `useCan()` hook from `lib/permissions/use-can.ts`. No role hardcoding. UX only.
8. **Routes:** Tabbed views via `?view=table` search param, not separate file-system routes. All paths via `routes` helper.
9. **PR Checklist:** typecheck, lint, test, no circular deps, no business in ui, no raw routes, no any, centralized queryKeys/routes, build passes
